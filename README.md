# 富文本门户的语义化录入与回读

editor-transfer 用于合作资料的本地查看和来源保存。当前版本支持人工触发的整份资料查看、字节级归档，以及把带结构的文档 JSON 通过门户的可见编辑工具栏录入本地草稿。资料对象按内容摘要保存，每次领取保留单独回执。自动组织领域资料的能力与人工查看入口分别演进。

## 运行环境

使用 Node.js 22。依赖已锁定；首次准备执行 `npm ci --ignore-scripts`，正式运行无需下载资料或软件。全部样例使用合成数据与本机来源，不连接生产系统。

```bash
npm run check
npm test
npm run demo
```

`npm run demo` 在临时目录实际读取资料、归档并重新核验摘要，退出时清理临时内容。浏览器项目还会启动本地门户和 Chromium 并完成可见页面查看；随后把 `fixtures/source/installation.json` 录入门户草稿，演示中途重新加载、保存延迟和一处不受支持的结构。浏览器在环境准备阶段安装，正式运行不下载。正常演示应在九十秒内结束。

## 本地来源门户

`fixtures/portal/` 是合成业务来源的页面与交互脚本，由 `src/portal.js` 提供本地 HTTP 服务；浏览器功能测试直接操作这些页面。

运行 `npm start -- --port 4173` 后访问终端显示的本地地址，按 Ctrl+C 停止；端口也可由 `PORT` 配置。

## 资料操作

```bash
npm run cli -- inspect fixtures/portal.json
npm run cli -- capture fixtures/portal.json .local/archive
npm run cli -- list .local/archive
npm run cli -- enter fixtures/source/installation.json
```

`capture` 只表示来源字节已保存，不声称领域流程已自动完成。已有查看功能只展示现有资料，不替代业务接纳判断。`scripts/create-fixtures.js` 用于维护者重建合成资料；运行与测试直接读取已提交的资料。

## 浏览器录入与回读

来源文档用 `blocks` 描述业务结构：`paragraph`、`warning`（门户的警告块）和 `list`（`ordered` 加嵌套 `items`）；每个文字 run 可带 `emphasis` 和 `link`。录入只通过门户页面上可见的按钮与键盘动作完成：

- 文字用输入法组合串提交（`composition` + `insertText`），不拼接 HTML。
- 标点、强调和链接都在浏览器实际产生的选区上，用工具栏按钮应用；选区被抢走时重新定位并重选。
- 列表层级用“增加缩进/减少缩进”和 Enter 完成，退出列表也用 Enter，不猜层级数字。
- 警告块用门户的“警告块”按钮切换格式；普通段落在离开警告块后显式切回“段落”。
- 不使用粘贴：门户粘贴只保留纯文本，会丢掉步骤、警告与链接；录入按块重建这些结构。也不依赖撤销栈，每一步以回读结果为准。

每个**可重试的编辑边界**是：核对页面修订号 → 录入一块 → 回读比较 → 点“保存草稿” → 点“重新读取” → 再次回读。成功以回读后的业务语义为准，而不是 HTML 字符串相等。比较忽略空白、NBSP、换行和 run 边界这类排版归一化；文字、步骤顺序、列表类型、强调位置和链接目标的变化都会报告差异。回读器遇到工具栏无法表达的 DOM（表格、标题、未知块等）会记为问题，边界失败而不是宣布成功。

**草稿修订号**是门户为每次保存分配的编号；它只证明该版本已写入草稿。门户没有可见的发布控件，因此录入结果始终为 `published: false`，并说明草稿修订不等于最终发布。

**不受支持的结构**（如 `fixtures/source/installation.json` 里的扭矩表）留在返回报告 `unsupported` 中，附原始 JSON 和原因。录入在第一个此类结构处停下，之后的受支持块列入 `pendingAfterGate` 并标记原因，不会删掉结构后继续，也不会把后续步骤越过它写入而改变顺序。

### 冲突、重载与人工修改

- 边界开始前先用可见的“重新读取”核对修订号；被他人推进就停止并说明，不写入。
- 编辑器中出现不在已核验前缀内的内容（例如人工粘贴的警告）时，先报告冲突并保留页面里的未保存内容，不直接重新读取覆盖。
- 保存等待期间他人抢先用同一修订号保存时，门户返回 409；录入停止，服务端保留他人版本。
- 冲突说明会给出本地核验前缀、服务端块数、他人版本中多出的块以及差异列表；是否合并由人工决定。录入之后不会重试覆盖。
- 中途重新加载（页面刷新或点“重新读取”）后，可用 `resume()` 从与服务端已持久化内容一致的最长前缀继续；前缀之后若有来源之外的额外内容，则停下并报告冲突。
- `saveDelay` 用于演示保存延迟；门户的自动保存与显式保存由页面自己的保存队列串行化，录入只采纳其产生的修订号。

## 目录约定

- `src/domain.js`：现有领域读取和查看接口。
- `src/archive.js`：内容对象、来源回执与完整性检查。
- `src/semantics.js`：来源 JSON → 可录入计划；回读模型的语义比较。
- `src/readback.js`：把门户 contenteditable 的可见 DOM 读回语义模型。
- `src/enter.js`：只通过可见交互的录入、编辑边界、保存/冲突与续录。
- `fixtures/`：本地资料、来源文档与领域配置。
- `test/`：已有行为的运行验证，使用独立临时目录。

## Linux 环境

`Dockerfile` 使用 Node.js 22 镜像；浏览器项目使用包含 Chromium 的运行镜像。可执行 `docker build -t editor-transfer:local .` 后运行 `docker run --rm --network none editor-transfer:local npm test`。测试中的 HTTP、MQTT 和门户都仅绑定回环地址；不需要第二个容器。构建阶段准备依赖，运行时不安装依赖。
